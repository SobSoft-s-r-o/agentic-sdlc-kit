# Plan 1 controller rulings

Decisions taken during subagent-driven execution of Plan 1 (core tracker), in order. Each binds the code on this branch; the spec remains the authority where a ruling is silent.

- **R1**: resultPublishedAt is set when publishing phase `delivery` OR the phase immediately preceding `delivery` in type.phases — simplest reading of spec §7 "result published" — cost if wrong: acceptance gating slightly early/late, local to stateMachine.
- **R2**: renderStageSummary input gets `needsApproval: boolean`; footer only when true — cost: none.
- **R3**: an "empty board" fixture includes the built-in Status field with GitHub defaults (Todo, In Progress, Done) — cost: none.
- **R4**: `sdlc approve <issue> approve` without --phase uses the task's current phase — cost: none.
- **R5**: project renamed to agentic-sdlc-kit (user request); package name agentic-sdlc-kit, bin sdlc.
- **R6**: duplicate custom type ids rejected in Task 2 config validation (carry into T2 dispatch) — cost: none.
- **R7**: Task 2 adds `typecheck` script (tsconfig.test.json covering tests) and rejects duplicate custom ids — reviewer minors 1,3 — cost: tiny.
- **R8**: Node floor/npm10 lockfile caveat documented in Plan 4 README — cost: none now.
- **R9**: zod 4 API is binding for Task 2.
- **R10**: Plan 2 installer must write `environment` explicitly per target (default rule depends on target count; adding a target would otherwise orphan deploy history) — cost if ignored: lost deploy evidence.
- **R11**: per-target quality_gate (spec §6 Q6) deferred to Plan 2; schema will need the field then.
- **R12 (spike/acceptance types for T3)**: resultPublishedAt set on stage_published of `delivery` or of the phase directly before `delivery` (spike exploration, analysis analysis) — per R1.
- **R13 (for T10 reconcile)**: deploy-type task in awaiting_deployment with empty pendingTargets → reconcile reports `error` action "no targets declared"; reconcile skips events on done tasks (TransitionError tolerated per task); `/ran` newer-than check is enforced by reconcile against the final PR mergedAt.
- **R14**: reopened → phase = type.phases[0], reopenedAt; terminal approvals must be newer than reopenedAt; finalMergedAt gates confirmed_ran; owner_acceptance final merge sets resultPublishedAt if unset.
- **R15**: confirmed_ran NOT gated on approval.at > finalMergedAt — finalMergedAt is record time, not GitHub merge time; reconcile enforces newer-than-merge using PR mergedAt (R13).
- **R16**: T10 reconcile reports `error` "unrecognised Scope value" when scopeRecognized=false (treats as final only after flagging).
- **R17 (T5)**: PrInfo gains `mergedAt?: string` (needed for /ran newer-than-merge, R13). listComments(n) works for issue or PR numbers (GitHub issues comments API); reconcile reads owner commands from the task issue AND its PRs (spec §8).
- **R18 (T7)**: fakeGh matches by exact arg element equality (script authors must use exact args). Real listComments filters createdAt > sinceIso client-side (GitHub `since` is updated_at). FakePr.issue is explicit link; GitHubTracker tests must cover body-based linking.
- **R19 (T7)**: add Tracker.listUntracked(): Promise<{issue:number;title:string;reason:string}[]> — sdlc:task issues with missing or corrupt state comment; listTrackedTasks skips (never throws on) corrupt comments. FakeTracker implements it too. T11 status uses it.
- **R20**: user requested MCP install — spec §2/§6/§12/§14 updated on main (77052c0); implementation belongs to Plan 2 (render per harness) + Plan 3 (doctor checks). Plan 1 unaffected.
- **R21**: board field renamed 'Task type' (GitHub reserves 'Type'); BoardFields.type key unchanged; spec+plan+constraints updated. Option updates must resend existing option ids (+color, description). Views via REST POST .../projectsV2/{n}/views with numeric field ids; check existing names first.
- **R22**: a failed view write is a failed GitHub write (non-zero exit per global constraint); viewsManual only when the API is unsupported (404/422 'not supported'), not on generic failure — global constraint outranks R21 wording — cost if wrong: one exit-code change.
- **R23 (T7)**: listSuccessfulDeployments treats latest status `success` OR `inactive` as succeeded — GitHub flips older successes to inactive; spec §10 "any past successful deployment satisfies a target" — cost if wrong: one constant.
- **R24 (T7)**: PrInfo carries body, no scope; callers use parsePrBody(pr.body). List limits throw at limit (no silent truncation). --paginate real-shape check goes into T11 sandbox smoke.
- **R25 (T7)**: state-comment trust = authenticated login ∪ cfg owners ∪ github-actions[bot] (case-insensitive). Multiple trusted state comments → read the one with newest updatedAt; writeState PATCHes that one, and if PATCH is refused (403/404) POSTs a new one. Teams with several agent logins → list them under owners for now (Plan 2 installer asks) — cost if wrong: duplicate state copies, newest wins.
- **R26 (T7)**: 'unknown current value' = item not read (just added) → clear empties; read item with absent value = empty, no clear. PATCH-403 fallback may leave a stale trusted copy; newest wins, no deletion.
- **R27 (T8)**: a --comment-url approval counts only if the comment is an owner command matching the action (spec §8: `/approve`, `/accept`, `/ran`, `/merge`, `/cancel <reason>`). Shared pure parser src/core/ownerCommand.ts `parseOwnerCommand(body) → {action, reason?} | null`: first non-empty line, trimmed, must start with `/<action>` followed by end or whitespace; case-insensitive; `/cancel` requires a non-empty reason; T10 reconcile reuses it. For cancel via comment, reason comes from the comment unless --reason given (then they must match? no: --reason overrides).
- **R28 (T8)**: `ran` gate uses the final PR's mergedAt, falling back to state.finalMergedAt; if neither exists the state machine already refuses (confirmed_ran needs finalMergedAt).
- **R29 (T8)**: Tracker gains authenticatedLogin(): Promise<string|undefined> (accepted). out() receives printable strings; T11 cli prints as given.
- **R30 (T8)**: comment approvals authored by the tracker's own login: enforce → refused ("authored by the agent's own login; approve via prompt or use a separate agent account"); observe → recorded with source `unverified`, ref kept. Edited comments (updatedAt > createdAt) refused. Cancel requires non-empty reason. taskSetType resets phase to new type's phases[0] when current phase not in new type. — cost if wrong: solo same-login users can't approve by comment in enforce until Plan 3 prompt log.
- **R31 (T8)**: a single owner /approve after the latest publication approves only the target phase (current unless --phase); time check per phase prevents reuse. No change.
- **R32 (T9)**: verify child stdout goes to our stderr (stdio ['inherit', 2, 'inherit']) so --json stays valid. urls = one per satisfied target (newest satisfying deployment). Dedup exact-SHA (case-insensitive), after verify, last 50 only — duplicates harmless.
